# dupfind 第 1 版设计

日期：2026-10-20  
状态：待用户确认后实现

## 问题

Windows 上常有同一份文件被复制到「下载 / 桌面 / 微信文件」多份。现有工具（如 fclones）很快、很强，但文档和默认体验偏英文、偏高手。需要一个中文、零依赖、默认只看不删的命令行工具。

## 目标

- 找出**内容完全相同**的文件（不是长得像的照片）
- 在 Windows 上用一条命令扫描某个文件夹（含子文件夹）
- 默认只报告，不删除、不移动
- 只用 Python 标准库，不装第三方包
- 公开到 GitHub，README 用中文，复制两条命令就能跑

## 非目标（第 1 版明确不做）

- 不删除、不移动、不回收站
- 不找相似图片
- 不做图形界面、TUI、HTML 报告
- 不跟随快捷方式 / 符号链接
- 不需要 GitHub Pages、不需要服务器

## 谁用

- 作者自己先用来扫下载目录
- 其他 Windows 用户：会打开终端、会复制命令即可

## 命令

```text
python dupfind.py 文件夹路径
python dupfind.py 文件夹路径 --min-size 1mb
python dupfind.py -h
```

规则：

- 路径必填。不存在或不是文件夹时，打印中文错误并以非 0 退出
- `--min-size` 可选。支持 `123`、`1kb`、`1mb`、`1gb`（大小写不敏感）。默认 `1` 字节，但仍**跳过空文件（0 字节）**
- 第 1 版没有 `--delete`

## 算法

1. 用 `os.walk` 遍历目标目录，不跟随链接
2. 只处理普通文件。遇到权限错误：计入「跳过」，继续
3. 文件大小为 0：跳过
4. 小于 `--min-size`：跳过
5. 先按大小分组。只有 1 个文件的大小组不再哈希
6. 同大小且多于 1 个：分块读取，计算 SHA-256（例如每块 1024 * 1024 字节），不把整个文件读进内存
7. SHA-256 相同且至少 2 个路径：视为一组重复
8. 扫描过程打印简单进度（已扫描文件数），避免看起来像卡死

## 输出

扫描结束后打印中文摘要和分组。示例：

```text
扫描完成：1234 个文件，跳过 5 个，发现 2 组重复，多占 80.0 MB

[1] 每个 40.0 MB，共 2 个
  D:\Download\a.mp4
  D:\Download\copy\a.mp4

[2] 每个 1.2 MB，共 3 个
  D:\Download\photo.jpg
  D:\Desktop\photo.jpg
  D:\Download\微信\photo.jpg
```

计算规则：

- 「多占」= 每组 `(文件数 - 1) * 单个大小` 的总和
- 组按浪费空间从大到小排序
- 没有重复时明确说「没有发现重复文件」，退出码 0
- 路径用绝对路径，便于复制

## 退出码

- `0`：运行成功（包括没有重复）
- `2`：参数或路径错误
- `1`：未预期的失败
